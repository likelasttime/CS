I/O 작업(파일 읽기, 네트워크 요청 등)을 수행할 때 호출한 함수가 제어권을 바로 반환하는지 여부를 나타내는 개념
<br>
프로그램의 성능과 응답성에 큰 영향을 미친다.
<br>
Blocking/Non-Blocking은 제어권 반환 관점이고, 동기/비동기는 작업 완료 알림 관점이다.
<br>
Node.js는 NonBlocking I/O를 기본으로 사용해서 단일 스레드로도 높은 동시성을 처리한다.
<br>
Java의 NIO(New I/O), Python의 asyncio도 NonBlocking I/O를 지원한다.
<br>
대규모 트래픽을 처리하는 서버일수록 NonBlocking I/O가 필수적이다.

<br>

### Blocking I/O
- I/O의 작업이 완료될 때까지 프로그램이 멈춰서 기다리는 방식
- 파일을 읽는 함수를 호출하면, 파일을 다 읽을 때까지 그 다음 코드로 진행하지 못 하고 대기하며 작업이 끝나야 제어권이 반환된다.
- 코드가 직관적이고 이해하기 쉽다.
- 순차적으로 실행되니 예측 가능하다.
- I/O 작업 중에는 다른 일을 못 하니 CPU가 놀고, 여러 요청을 처리하려면 스레드를 많이 만들어야 해서 리소스 낭비가 심하다.

<br>

### Non-Blocking I/O
- I/O 작업을 요청한 후 결과를 기다리지 않고 바로 제어권을 반환하는 방식
- 작업이 완료되지 않았더라도 일단 다른 일을 할 수 있다.
- 나중에 결과가 준비되었는지 확인하거나(폴링), 콜백으로 통보받을 수 있다.
- 하나의 스레드로도 여러 I/O 작업을 동시에 처리할 수 있어 효율적이다.
- CPU를 낭비하지 않는다.
- 코드가 복잡해지고(콜백 지옥), 에러 처리가 어려우며, 결과가 준비되었는지 계속 확인해야 할 수도 있다.

<br>

### Blocking + 동기
- 기다리면서 완료될 때까지 대기
- 가장 일반적이다.

<br>

### Non-Blocking + 비동기
- 바로 반환하고, 완료되면 콜백으로 알린다.

<br>

### Non-Blocking + 동기
- 바로 반환하지만, 계속 완료 여부를 확인(폴링)
