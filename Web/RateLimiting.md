특정 시간 동안 사용자나 IP가 보낼 수 있는 요청 횟수를 제한하는 기술
<br>
ex) 1분에 최대 100번만 API 호출 가능처럼 제한을 둔다.
<br>
서버 보호(과도한 요청으로 인한 서버 과부하 방지), DDoS 공격 방어(악의적인 대량 요청 차단), 공정한 리소스 분배(특정 사용자가 서버를 독점하지 못 하게 함), 비용 절감(불필요한 API 호출 감소로 서버 비용 절감)과 같은 이유로 Rate Limiting이 필요하다.
<br>
#### 구현 방식
1️⃣ Fixed Window: 1분 단위로 카운트를 초기화한다. 간단하지만 경계 시점에 문제가 발생할 수 있다.
<br>
2️⃣ Sliding Window: 정확한 시간 기준으로 카운트한다. 더 정확하지만 복잡하다.
<br>
3️⃣ Token Bucket: 토큰을 일정 속도로 채우고, 요청 시 토큰을 소비하므로 유연하다.
<br>
실무에서는 Redis를 많이 사용하며 빠른 읽기/쓰기와 TTL(만료 시간) 기능을 활용해서 사용자별 요청 횟수를 카운트하고 제한한다.
