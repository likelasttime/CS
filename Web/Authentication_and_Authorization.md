- 실무에서 JWT(Q27)나 OAuth 2.0(Q44)를 사용해서 인증을 구현하고, 세션(Q9)이나 쿠키에 역할 정보를 저장해서 인가를 처리
- 인증 없이 인가는 불가능하다.
- 인증이 됐다고 모든 것을 할 수 있는 건 아니다.

<br>

### 인증(Authentication)
- 사용자의 신원을 확인하는 과정
- 1️⃣ 지식 기반: ID/비밀번호
- 2️⃣ 소유 기반: OTP, 휴대폰 인증
- 3️⃣ 생체 기반: 지문, 얼굴 인식
- 4️⃣ 다중 인증(MFA): 여러 방법을 조합

<br>

### 인가(Authorization)
- 사용자에게 특정 권한이 있는지 확인하는 과정
- 1️⃣ 역할 기반(RBAC): 관리자, 일반 사용자와 같은 사용자의 역할로 권한 부여
- 2️⃣ 속성 기반(ABAC): 부서, 직급과 같은 사용자의 속성으로 권한 부여
- 3️⃣ ACL(Access Control List): 각 리소스마다 접근 가능한 사용자 목록 관리

<br>

### 구현 흐름
- 1️⃣ 사용자가 ID, PW를 입력하여 로그인 시도
- 2️⃣ 인증: 서버가 DB에서 사용자 정보를 확인하여 맞으면 토큰 발급
- 3️⃣ 게시글 삭제와 같은 사용자의 특정 기능 요청
- 4️⃣ 인가: 서버가 토큰 확인 및 사용자의 권한 확인
- 5️⃣ 권한이 있으면 허용하고 없으면 거부(403 Forbidden)
