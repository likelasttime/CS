### 멱등성
- 같은 요청을 여러 번 해도 결과가 동일한 성질
- 한 번 실행하든 백 번 실행하든 시스템 상태가 같다.
- 요청이 타임아웃되어 재시도할 때 중복 처리 방지
- 버튼을 여러 번 클릭해도 안전
- 메시지가 중복 전달되어도 안전하게 처리
- 결제 API는 같은 주문을 여러 번 결제하면 안 되니까 멱등키를 사용한다.
- 이메일 발송은 같은 이메일을 여러 번 보내면 안 되니까 발송 기록을 확인한다.
- PUT으로 "재고 = 10"으로 설정하면 멱등하고 POST로 "재고 - 1"하면 비멱등

<br>

#### 멱등한 메서드
- GET: 조회만 하니까 몇 번을 해도 데이터는 그대로
- PUT: 전체 리소스를 교체한다. 같은 내용으로 여러 번 교체해도 결과는 동일하다.
- DELETE: 이미 삭제된 리소스를 또 삭제해도 동일하다.
- HEAD, OPTIONS: 정보만 조회하므로 멱등하다.

<br>

### 비멱등한 메서드
- POST: 매번 새로운 리소스가 생성된다.
- PATCH: 부분 수정. 구현에 따라 다르다.

<br>

### 멱등성 보장하기
- 멱등키(Idempotency Key): 클라이언트가 고유 키를 함께 전송
  - 결제 API에서 같은 키의 요청은 한 번만 처리
  - Stripe, PayPal 등 결제 API에서 사용
- 조건부 요청: If-Match 헤더로 리소스 버전 확인
  - 낙관적 락(Q53)과 비슷한 개념
-  상태 확인: 작업 전에 현재 상태를 확인하고 처리
  - 예) 이미 주문 완료 상태면 다시 처리하지 않는다.
