Stateful과 Stateless는 서버가 클라이언트의 상태 정보를 유지하는지 여부에 따른 통신 방식의 차이다.

### Stateful
- 서버가 클라이언트의 이전 상태를 기억하고 있는 방식
- 서버는 클라이언트와의 연결 정보, 세션 데이터 등을 메모리에 저장해두고 다음 요청에서 활용한다.
- 연결 정보를 유지하므로 효율적이다.
- 서버가 상태를 저장해야 해서 메모리를 많이 사용하고, 특정 서버에 종속되어 Scale Out이 어려워서 서버 장애시 세션 정보가 손실될 수 있다.
- WebSocket이 대표적인 예다.

<br>

### Stateless
- 서버가 클라이언트의 이전 상태를 전혀 기억하지 않는 방식
- 매 요청은 독립적이고, 서버는 이전에 어떤 요청이 왔는지 알지 못한다.
- 클라이언트는 매번 필요한 모든 정보를 요청에 포함시켜 보내야 한다.
- HTTP 프로토콜이 대표적인 Stateless 프로토콜이다. 세션이나 쿠키를 사용해 Stateful처럼 동작하게 만들 수 있다.
- 서버가 상태를 저장하지 않아 메모리 효율적이고, Scale Out이 쉽다.(어느 서버로 요청이 가도 상관없다.)
- 서버 장애 시에도 다른 서버로 쉽게 대체 가능하다.
- 매 요청마다 모든 정보를 전송하기 때문에 데이터 전송량이 많고, 인증 정보를 매번 검증해야 한다.
- REST API는 Stateless 설계 원칙을 따르는 대표적인 예다.
- JWT 같은 토큰 기반 인증으로 Stateless 방식을 유지하면서도 사용자 인증을 처리하는 게 트렌드다.
- 대규모 서비스일수록 Stateless 설계를 선호하는데 이는 수평 확장과 고가용성을 위해서다.
