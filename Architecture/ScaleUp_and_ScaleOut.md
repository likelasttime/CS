Scale Up과 Scale Out은 서비스의 처리 용량을 늘리는 2가지 대표적인 확장 전략이다.
<br>
사용자가 늘어나거나 트래픽이 증가할 때 시스템의 성능을 향상시키는 방법이다.
<br>
초기에는 Scale Up으로 시작해서 빠르게 구축하고, 트래픽이 증가하면 Scale Out으로 전환하는 전략도 많이 사용된다.

<br>

### Scale Up
- 수직 확장
- 기존 서버의 성능을 업그레이드 하는 방식
- CPU를 더 빠른 것으로 교체하거나 RAM을 8GB에서 32GB로 늘리거나 더 좋은 디스크로 바꾸는 거다.
- 1대의 서버를 더 좋게 만든다고 생각하면 된다.
- 구현이 간단하고, 추가 설정이 필요없다.
- 데이터 정합성 관리가 쉽다.
- 하드웨어 성능의 한계가 있다. (무한정 업그레이드 불가)
- 비용이 기하급수적으로 증가하며, 단일 장애점(SPOF)이 된다.
- 서버 1대가 다운되면 전체 서비스가 중단된다.

<br>

### Scale Out
- 수평 확장
- 서버의 개수를 늘리는 방식
- 1대로 운영하던 서버를 N대로 늘려서 여러 서버가 부하를 나눠서 처리하도록 한다.
- 로드 밸런서를 통해 트래픽을 여러 서버에 분산한다.
- 이론상 무한 확장이 가능하다.
- 저렴한 서버를 여러 대 확장해서 사용하므로 비용 대비 효율적이다.
- 고가용성을 확보할 수 있다.
- 구현이 복잡하고, 세션 관리나 데이터 동기화가 어렵다.
- 로드 밸런서와 같은 추가 인프라가 필요하다.
- 대부분의 대규모 서비스에서 Scale Out을 선택한다.
- AWS, Netflix, Google과 같은 회사들은 모두 수평 확장을 기본으로 한다.
- 데이터베이스는 Scale Out이 어려워서 샤딩이나 Read Replica와 같은 기법을 함께 사용한다.
