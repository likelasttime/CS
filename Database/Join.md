### inner join
<img width="276" height="207" alt="image" src="https://github.com/user-attachments/assets/0d4849f8-5b42-4951-a554-723b3a001ff9" />

- 교집합
- 양쪽에 모두 존재하는 데이터만 반환
- `SELECT {필드} FROM {테이블} JOIN {필드} ON {조건}`를 `SELECT {필드} FROM {테이블1}, {테이블2} WHERE {조건}`으로 표현할 수도있다.

  <br>

  ### left outer join
  <img width="277" height="207" alt="image" src="https://github.com/user-attachments/assets/aa480744-1fea-4bf5-b365-6ced612710b6" />

  - 왼쪽 외부 조인
  - 왼쪽 테이블을 기준으로 오른쪽 테이블과 조인한다.
  - 조인 조건과 일치하지 않더라도 왼쪽 테이블의 결과는 최종 결과에 포함
  - `SELECT {필드} FROM {테이블} LEFT OUTER JOIN {필드} ON {조건}`
  - 오른쪽 외부 조인보다 왼쪽 외부 조인을 사용하는 게 좋다.
 
<br>

### right outer join
<img width="275" height="193" alt="image" src="https://github.com/user-attachments/assets/935351a6-a757-4964-982b-817a603db366" />

- 오른쪽 외부 조인
- 오른쪽 테이블 기준으로 왼쪽 테이블과 조인
- 조인 조건과 일치하지 않더라도 오른쪽 테이블의 결과는 최종 결과에 포함
- `SELECT {필드} FROM {테이블} RIGHT OUTER JOIN {필드} ON {조건}`

<br>

### cross join
- 교차 조인
- 데카르트 곱이라고 하는 곱집합 개념
- 조인에 참여하는 테이블에서 발생할 수 있는 모든 조합을 찾아내어 반환
- 내부 조인에 비해 수십 배에서 수백 배 이상 많은 데이터양을 얻을 수 있다.
- 시간적, 공간적 리소스 점유 측면에서 오버헤드가 발생하는 만큼 주의해야 한다.
- `SELECT {필드} FROM {테이블1} CROSS JOIN {테이블2}`를 `SELECT {필드} FROM {테이블1}, {테이블2}`로 표현할 수도 있다.

<br>

### natural join
- 2개 테이블에 동일한 열명이 있을 때 조인 조건절을 따로 작성하지 않아도 자동으로 조인을 수행하는 방식
- 조인이 제대로 성사되면 내부 조인과 동일한 결과가 출력된다.
- 조인하는 열들의 데이터 유형이 서로 달라도 자연 조인이 수행된다.
- 명시적으로 작성해야 할 키워드는 `NATURAL JOIN`이다. 조인 조건절을 알아서 찾아주므로 직접적인 조인 조건문은 작성하지 않는다.
  - 만약 `ON 학생.학번 = 지도교수.학번`과 같은 구문을 작성하면 에러가 발생
 
- `SELECT {필드} FROM {테이블1} NATURAL JOIN {테이블2}`
- 동일한 열명이 있을 때 내부 조인으로 수행된다.
- 동일한 열명이 없으면 발생 가능한 경우의 수를 모두 조합하는 교차 조인으로 수행된다.
- 열명 변경에 따라 출력 결과가 달라지며 의도치 않은 결과로 출력될 가능성이 높아 일반적으로 잘 활용하지 않는다.

<br>

### 드라이빙 테이블과 드리븐 테이블
- 다수의 테이블에서 조인을 수행할 때는 동시에 여러 개의 테이블에 접근할 수 없기 때문에 접근하는 우선순위를 정해야 한다.
- 테이블에 접근하는 선후 관계에 따라 드라이빙 테이블과 드리븐 테이블로 구분한다.
- 먼저 접근하는 테이블이 드라이빙 테이블(outer table)이다.
- 드리븐 테이블(inner table)은 드라이빙 테이블 다음으로 접근한다.
- 드라이빙 테이블을 무엇으로 선정할지가 매우 중요하다.
- 적은 결과가 반환될 것으로 예상되는 드라이빙 테이블을 선정하고, 조인 조건절의 열이 인덱스로 설정되도록 해야한다.

<br>

### 조인 알고리즘
- 중접 루프 조인은 데이터 접근 시 인덱스에 의한 랜덤 엑세스가 있어서 엑세스할 데이터의 범위가 넓다면 비효율적인 조인 방식이다. 
- nested loop join
  - 중첩 루프 조인
  - 드라이빙 테이블의 데이터 1건당 드리븐 테이블을 반복해 검색
  - 양쪽 테이블에 공통된 데이터를 출력
- block nested loop join
  - 블록 중첩 루프 조인
  - 중접 루프 조인의 효율성을 높이고자 만들어졌다.
  - 드라이빙 테이블에 대해 join buffer라는 개념을 도입하여 조인 성능의 향상을 할 수 있다.
  - 1️⃣ 드라이빙 테이블에서 조건에 맞는 데이터를 검색
  - 2️⃣ 검색된 데이터를 조인 버퍼에 가득 채워질때까지 적재
  - 3️⃣ 조인 버퍼와 데이터를 조인하는 방법을 반복하며 B 테이블의 데이터에 모두 접근
  - 조인 버퍼의 데이터들과 B 테이블의 1번의 table full scan으로 원하는 데이터를 모두 찾는다.
  - B 테이블의 테이블 풀 스캔을 줄임으로써 성능 저하를 개선하는 조인 알고리즘이다.

- batched key access join
  - BAK 조인 또는 배치 키 액세스 조인
  - 접근할 데이터를 미리 예상하고 가져온다.
  - 블록 중첩 루프 조인에서 활용한 드라이빙 테이블의 조인 버퍼 개념을 그대로 사용한다.
  - 드리븐 테이블의 데이터를 예측하고 정렬된 상태로 버퍼에 적재하는 기능을 multi range read라고 한다.
  - 드리븐 테이블에 대해 시퀀셜 액세스를 수행
  - 1️⃣ 드라이빙 테이블에서 필요한 데이터를 추출하여 조인 버퍼에 적재
  - 2️⃣ 드리븐 테이블의 인덱스를 기반으로 필요한 데이터를 예측하여 랜덤 버퍼에 적재
  - 3️⃣ 조인 조건절로 비교
  - 4️⃣ 동일한 데이터가 있다고 판단되면 드리븐 테이블의 데이터에 접근하고 결과를 조인하여 반환

- hash join
  - MySQL 8.0.18 버전부터 지원되는 조인 방식
  - 기존의 중첩 루프 조인 방식에서 조금 개선된 버전인 블록 중첩 루프 조인과 배치 키 액세스 조인의 한계를 탈피
  - 조인에 참여하는 각 테이블의 데이터를 내부적으로 해시값을 만들어 내부 조인을 수행
  - 해시값으로 내부 조인을 수행한 결과는 조인 버퍼에 저장
  - 조인 열의 인덱스를 필수로 요구하지 않아도 된다.
  - 보통 대용량 데이터의 동등 비교 연산에서 확인할 수 있다.
