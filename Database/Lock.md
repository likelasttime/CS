### Lock
- 락은 여러 사용자가 동시에 같은 데이터를 수정하려 할 때 데이터 충돌을 방지하기 위한 매커니즘
- JPA/Hibernate에서 `@Version` 어노테이션으로 낙관적 락, `@Lock(LockModeType.PESSIMISTIC_WRITE)`로 비관적 락을 쉽게 구현할 수 있다.
- 대부분의 경우 낙관적 락이 성능상 유리하지만, 결제나 재고 관리처럼 절대 충돌이 생기면 안 되는 경우는 비관적 락을 사용한다.

<br>

|비관적 락(Pessimistic Lock)|낙관적 락(Optimistic Lock)|
|---------------------------|-------------------------|
|데이터를 읽을 때 바로 락을 걸어서 다른 트랜잭션의 접근 차단 <br> 충돌 없이 안전하게 데이터 보호 <br> 성능 저하, 교착 상태(Q10) 가능성 <br> 충돌이 자주 발생하는 경우, 데이터 정합성이 매우 중요한 경우 주로 사용한다. <br> `SELECT * FROM products WHERE id = 1 FOR UPDATE`와 같이 행 단위 락 <br> 예를 들어, 은행 계좌 이체 시 잔액을 확인하고 돈 빼는 동안 다른 작업을 차단|데이터를 읽을 때는 락 없이 읽고, 수정할 때 버전을 확인해서 충돌 감지 <br> 데이터에 version 컬럼 추가해서 구현 <br> 락이 없어서 성능이 좋음, 교착 상태 없음 <br> 충돌 시 재시도 필요 <br> 충돌이 드문 경우 읽기가 많고 쓰기가 적은 경우 주로 사용 <br> 예를 들어, 블로그 게시글 수정 시 여러 명이 동시에 같은 글을 수정할 확률이 낮다.|
