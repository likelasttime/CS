### 인덱스
- 실제 데이터 위치를 식별하고 데이터 접근 속도를 높이고자 생성되는 키 기준으로 정렬된 오브젝트
- 생성하려는 열의 속성에 따라 고유 인덱스(unique index)와 비고유 인덱스(non-unique index)로 구분할 수 있다.
  - 비고유 인덱스를 주로 사용한다.
- 인덱스로 정의된 열 기준으로 순차 정렬된다.
- 인덱스를 이용해 테이블의 데이터를 찾아가는 과정에서 임의 접근 방식인 random access가 발생한다.
- 랜덤 액세스를 줄일 수 있도록 데이터의 액세스 범위를 좁히는 방향으로 인덱스를 설계하고 조건절을 작성해야 한다.
- 랜덤 액세스를 유발하는 인덱스는 기본 키가 아닌 비고유 인덱스일 경우에 해당한다.
- 기본 키는 클러스터형 인덱스이므로 기본 키의 순서대로 테이블의 데이터가 적재되어 었어 조회 효율이 매우 높다.
- 데이터를 추가, 수정, 삭제할 때마다 인덱스 정보도 함께 업데이트되어야 한다.
- 인덱스 자체도 공간을 차지해서 데이터베이스 용량이 늘어난다.

<br>

### 고유 인덱스
- 인덱스를 구성하는 열들의 데이터가 유일하다.
- 고유 인덱스는 `NULL`을 입력할 수 있다는 점이 기본 키와 큰 차이점이다.
- 고유 인덱스를 추가하는 DDL문 예시 `ALTER TABLE {테이블명} ADD UNIQUE INDEX {인덱스명}{(열)};`

<br>

### 비고유 인덱스
- 고유 인덱스에서 데이터의 유일한 속성만 제외한 키
- 데이터가 신규 입력되어 인덱스가 재정렬되더라도 인덱스 열의 중복 체크를 거치지 않고 단순한 정렬 작업을 수행
- 비고유 인덱스를 추가하는 DDL문 예시 `ALTER TABLE {테이블명} ADD INDEX {인덱스명}{(열)};`
