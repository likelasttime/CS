### MySQL
- 1995년 오픈소스로 배포된 무료 DBMS
- 2010년 MySQL이 Oracle에 인수됨
- 상용 버전과 커뮤니티 버전으로 구분됨
- 커뮤니티 버전의 라이선스는 GPL(General Public License)이며, MySQL 소스 코드 공개의 부담이 있고 제약된 기능과 서비스만 사용할 수 있다.
  - 1) MySQL이 설치된 소프트웨어를 판매
  - 2) 고객의 장비에 이미 MySQL이 설치된 상태에서 소프트웨어를 제공
  - 위의 2가지 경우는 소스 코드를 반드시 공개해야 함
- MySQL은 물리적인 DB 서버마다 독립적으로 스토리지를 할당하여 구성함
  - 보통은 master-slave 구조가 대부분이다.
  - master 노드는 쓰기와 읽기 처리를 모두 수행 가능
  - slave 노드는 읽기 처리만 수행 가능
  - 동일한 구문이 처리되지 않을 수 있다.
    - 쿼리문이 수행하는 서버의 위치를 파악하고 튜닝을 진행하면 물리적인 위치 특성이 내포된 쿼리 튜닝을 수행 가능
  - 각 DB 서버의 운영체제 설정, 할당된 스토리지 크기, 시스템 변수, 하드웨어 사양 등이 같을 때는 마스터 노드 중심으로 쿼리 튜닝을 진행해도 됨
- 대부분 중첩 루프 조인 방식을 이용해 조인을 수행함
- 데이터를 저장하는 스토리지 엔진이라는 개념을 포함하고 있어서 오픈소스 DBMS를 바로 꽂아서 사용할 수 있는 확장성이 특징이 있으며, plug & play 기능이라고 한다.
- Oracle 대비 메모리 사용률이 상대적으로 낮다. 1MB 메모리 환경에서도 데이터베이스를 운영할 수 있을 정도다.
- 신규 데이터가 생성될 때 증가하는 순번을 자동으로 매기는 '자동 증갓값'을 MySQL에서는 2가지 방법으로 저장할 수 있다.
  - 1) 특정 열의 속성으로 자동 증가하는 값을 설정하는 auto_increment
  - 2) 시퀀스 오브젝트를 생성한 뒤 호출
- 상용 DBMS와 다르게 수행된 쿼리 결과가 메모리에 적재되는 캐시 기능에 한계가 있다.
  - 데이터가 변경되면 캐시된 내용을 모두 삭제
