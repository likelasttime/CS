### 오브젝트
|용어|의미|
|---|-----|
|파서(parser)|MySQL 엔진에 포함되는 오브젝트 <br> 사용자가 요청한 SQL문을 쪼개 최소 단위로 분리하고 트리를 만든다. <br> 트리를 만들면서 문법 검사도 한다.|
|전처리기(preprocessor)|MySQL 엔진에 포함되는 오브젝트 <br> 파서에서 생성한 트리를 토대로 SQL문에 구조적인 문제가 없는지 파악한다. |
|옵티마이저(optimizer)|MySQL의 핵심 엔진 중 하나다. <br> 파서 트리를 토대로 필요하지 않은 조건은 제거하거나 연산 과정을 단순화한다. <br> 실행계획을 수립하며 옵티마이저가 선택한 최적의 실행 계획이 최상의 실행 계획을 보장하지 않는다.|
|엔진 실행기(engine executor)|MySQL 엔진과 스토리지 엔진 영역 모두에 걸치는 오브젝트 <br> 옵티마이저에서 수립한 실행 계획을 참고하여 스토리지 엔진에서 데이터를 가져온다.|

<br>

### SQL문 처리 과정
1. 사용자가 SQL문 수행
2. 파서는 MySQL이 이해할 수 있는 최소 단위(>, <, =등의 기호 및 SQL 키워드)로 구성요소를 분리하고 트리를 생성
   - 트리를 만드는 과정에서 문법 오류가 있는지 검토하고, 이상이 있으면 에러 발생과 동시에 실행 종료   
3. 전처리기(preprocessor)는 생성된 트리 결과를 토대로 유효성을 검증하고, 유효하지 않은 오브젝트가 있거나 권한이 없는 오브젝트를 호출하면 바로 에러를 발생
    - 이미 만들어진 테이블이나 뷰 등으로 구성되지 않는지
    - 존재하지 않은 열을 포함하지 않는지
    - 조회 권한이 없는 테이블을 조회하는지 등
4. 옵티마이저(optimizer)는 트리를 구성하는 오브젝트의 데이터를 효율적으로 가져오기 위해 시간은 적게 소요되면서도 비용 효율적인 경로로 데이터를 검색하는 방법에 대한 실행 계획을 수립
5. 엔진 실행기(engine executor)는 이전에 수립된 실행 계획으로 스토리지 엔진을 호출해 필요한 데이터를 가져온다.
6. 엔진 실행기는 스토리지 엔진을 통해 가져온 데이터 중 불필요한 데이터를 필터링하여 사용자가 원하는 결과를 전달
