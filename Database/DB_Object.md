### 테이블
- 데이터를 저장하는 오브젝트로 행과 열의 정보를 담는다.
- 테이블에서는 저장 방식과 저장 구조에 따라 스토리지 엔진 속성을 정의할 수 있다.
- InnoDB 스토리지 엔진은 보통 OLTP 환경에서 주로 사용하는 기본 DB 엔진이다.

<br>

### row
- 테이블에서 행을 의미한다.
- 동일한 구조의 데이터 항목들의 집합이다.
- 모든 행의 집합이 테이블이다.
- 행 수가 많아지면 데이터에 접근하는 과정에서 시간이 오래 소요될 가능성이 높다. 👉 partitioning 기법으로 SQL문의 성능 향상을 검토할 필요가 있다.

<br>

### column
- 테이블에서 열을 의미한다.
- 사전에 정의한 데이터 유형으로 데이터값을 저장하며, 열별로 다른 데이터 유형을 가질 수 있다.

<br>

### primary key
- 특정 행을 대표하는 열을 가리키는 용어
- 상황에 따라 2개 이상의 열을 조합해 기본 키를 구성할 수 있다.
- 기본 키를 활용하여 인덱싱할 수 있다.
- MySQL/MariaDB에서 clustered index로 작동한다.
  - 기본키의 구성 열 순서를 기준으로 물리적인 스토리지에 데이터가 쌓인다.
  - 비슷한 기본 키 값들이 근거리에 적재되므로 기본키를 활용하여 인덱스 스캔을 수행하면 테이블 데이터에 더 빠르게 접근할 수 있다.
 
<br>

### foreign key
- 외부에 있는 테이블(부모 테이블)을 항상 참조하면서 외부 테이블의 데이터가 변경되면 함께 영향을 받는 관계를 설정하는 키

<br>

### index
- 데이터베이스에서 키값으로 실제 데이터 위치를 식별하고 데이터 접근 속도를 높이고자 생성되는 키 기준으로 정렬된 오브젝트

<br>

### view
- 가상 테이블
- 일부 데이터에 대해서만 데이터를 공개하고, 노출에 민감한 데이터는 제약을 설정할 수 있어서 보안성이 좋다.
- 여러 개의 테이블을 join하면 성능을 고려한 최적화된 뷰를 생성함으로써 일관된 성능을 제공할 수 있다.
- 테이블의 데이터를 변경하면 뷰에서도 변경된 데이터를 조회할 수 있다. 반대의 경우도 마찬가지다.
- `CREATE VIEW {뷰 이름} AS SELECT {필드명} FROM {테이블명};`
